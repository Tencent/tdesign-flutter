# 组件 Demo 二次设计复核与收敛

## 背景

二次走查覆盖 28 个公开 Demo。仅依据修改日志或组件测试无法证明问题已经修复，必须把设计稿、`origin/develop` 和当前实现置于同一裁切边界下复核，并区分 Demo 组装、组件默认行为、共享 Token 与测试基线的所有权。

## 目标

- 逐一复核 Button、Indexes、Navbar、SideBar、TabBar、Tabs、Cascader、Checkbox、DateTimePicker、Input、Slider、Stepper、Textarea、TreeSelect、Avatar、Badge、Collapse、Empty、Footer、Image、ImageViewer、Progress、Swiper、Table、Tag、TimeCounter、DropdownMenu、Popover。
- Demo 只负责公开示例的状态与外部排列，不通过特殊样式掩盖组件缺陷。
- 组件默认视觉、交互与 API 在组件层收敛；共享色值由 Token 统一提供。
- 为设计稿提供可分别定位 develop/current 差异且区分配准视图与真实页面流的五栏证据，并为全部变更 Golden 提供可审计的三栏像素证据。

## 非目标

- 不要求 Flutter 与 Figma 使用同一字体栅格器，也不把合理的平台字体差异当作组件缺陷。
- 不机械复制小程序 props/events；小程序仅用于确认视觉语义和 Token 设计。
- 不在 Demo 中添加只为截图对齐的装饰、位移、裁剪或局部主题覆盖。
- 不修改 `tdesign-component/CHANGELOG.md`。

## 行为契约

- 页面截图从第一个公开标题开始，移除设备状态栏、Figma 头部与底部测试区域，五列使用一致的内容边界。
- 设计比较图固定为：Figma 原图、配准后的 `develop × Figma` 差异、配准后的 `current × Figma` 差异、当前分段配准渲染、当前原始渲染。配准只允许平移分段，禁止缩放组件；原始渲染必须保留累计纵向偏移，避免配准过程掩盖 Demo 行盒或间距问题。
- Golden 比较图固定为：`origin/develop` 基线、逐像素精确差异、当前基线；任一 RGBA 通道不同即在中栏标红。
- Golden 新增项以空白 develop 基线表示，删除项以空白当前基线表示，不能从证据清单中省略。
- `TProgress` 使用六个命名构造函数表达形态；形态无效参数不进入对应构造函数，`status` 是任务状态的唯一入口。
- `TCheckbox` 单行内容垂直居中，多行内容顶部对齐；方形指示器使用 1.5px 圆角。
- `TFooter` 的品牌内容允许与说明文案组合；链接分隔间距与颜色来自语义 Token。
- `TSwiper` 的卡片间距、缩放与淡化由组件实现，Demo 不补绘卡片效果。
- `TCell.note` 在有主内容时采用受约束的自然宽度，避免固定等分导致 Cascader 等页面错位。
- Popover 角落 placement 的气泡边缘与触发按钮边缘对齐，箭头保持 12px 内边距。
- Popover 点击另一触发器时，单次点击同时关闭旧气泡并打开新气泡；再次点击当前触发器仅关闭当前气泡。
- 灰阶 Token 与移动端设计值一致；所有消费页面的预期 Golden 变化必须一起审查。
- `TSlider.variant` 作为滑块结构形态的唯一入口：`normal` 默认使用 4px 轨道，`capsule` 由组件提供 24px 外轨、四周 3px 内缩的 18px 激活轨道、20px 游标与胶囊刻度；两种形态的轨道都使用 16px 水平内缩，Demo 不通过局部 `SliderTheme` 或额外水平间距补画组件形态。
- 胶囊型离散刻度仅在轨道内部绘制分隔线；两端保留 0/100 刻度文字，但轨道起点和终点不绘制分隔线。单游标与双游标使用相同规则，普通细轨道的圆点刻度保持原样。
- 普通离散 Slider 的刻度点半径为 3px，保证刻度超出 4px 轨道后在激活段仍可辨识，并同时作用于单值与区间形态；刻度文字与轨道端点使用同一组 16px 坐标。
- TabBar 胶囊容器使用全圆角与基础层级阴影；纯文本徽标与图标类标签共用内容右上角锚点，不在 Demo 中逐项偏移；双层菜单弹层未显式配置时使用主题 `radiusDefault`，显式 `radius` 仍优先。
- Cascader 的层级箭头使用 `textColorPrimary`；选项标题文字到首个选项文字的最终可见间距为 24px，不把 24px 重复加到选项行自带的内边距上。
- TreeSelect 的选中根节点由组件绘制 3px × 16px 品牌色左侧指示条。
- Input 的错误状态由组件使用错误色绘制清除图标，Demo 不再通过局部 Theme 模拟默认状态；错误表单项顶部对齐仍由 Demo 组合参数负责。Empty、Tag 的本轮差异属于公开 Demo 初始参数：自定义空状态使用二级容器背景、超长标签沿用默认填充形态。
- Input 紧凑示例的示例内容不再重复补页面已经提供的 16px 尾间距；带操作行不附带设计稿中不存在的帮助文案，验证码和密码只调整公开示例初始状态，不覆盖组件样式。
- Textarea 的标签和输入内容由组件按文本基线对齐，固定高度场景中的计数器由组件保持距底部 16px；字符限制 Demo 使用设计稿对应的 128px 高度与两行最小输入区域，竖排示例以占位文本表达未输入状态，卡片示例不再和后续模块间距叠加底部 Padding。
- DropdownMenu 单选项保持主文字色，仅选中图标和菜单标题使用品牌色；公开单选 Demo 初始选中“最火产品”，比较时必须使用实际展开态。
- Tag 的颜色、边框和尺寸仍由组件语义参数负责；Demo 只按设计稿组织展示型状态、可选形态和两行尺寸示例，不通过容器着色模拟标签。
- 水平 `TFormItem` 的标签区域与内容区域由组件保持 16px 间距。Slider 保持 Material 交互区域语义，设计稿中的 56px 示例行及白灰分层属于 Demo 布局，不通过扩大组件固有高度实现。Slider 单值示例和 Tag 可选标签的初始位置属于各自 Demo 数据与分栏布局，不上升到通用 Demo 框架。
- Golden 字体缺字应由对应页面声明已有的字形子集解决；不得接受缺字快照，也不得为单页缺字扩大通用测试框架的默认字体集合。
- `compactDemo` 的公共页面壳负责灰色页面底与白色示例内容块的分层；透明背景组件不得在单页 Demo 内自行补白，也不得把公共壳缺失误判成组件背景色。
- Input 基础示例的必填标记位置配置属于可复制示例本身，不由页面级 Theme 隐式注入。
- `TButton` 的图标插槽在未显式配置 `TLoadingThemeData.iconColor` 时，将按钮已解析的图标色传给插槽内的 `TLoading`；`TLoading` 独立使用的默认色不变，Demo 不单独强制白色。
- Demo 框架重构不得改变现有页面像素输出或组件交互；紧凑模式专属的内容间距与容器表面收敛到单一配置对象，默认配置保持透明表面和 16px 内容间距。
- 仅页面壳可以绘制紧凑 Demo 的容器表面；公开示例 Widget 不依赖页面基础设施，也不把页面背景、间隔或代码映射配置带入可复制示例。
- 删除没有实际调用的单页逃逸入口和无效参数；普通布局的页面级示例外边距使用与实现一致的命名，不以 `padding` 表达实际 `margin`。
