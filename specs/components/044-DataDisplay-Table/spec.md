# Table 设计说明

## 背景与目标

以下保留设计形成时的问题与依据；已修复的问题不表示当前代码仍有同一缺陷。

列宽、固定区、合并单元格和受控选择需要一致的约束与身份模型。

当前 Table 已完成强类型、受控排序与受控选择改造，但公开 Demo 与 Figma 节点 `28633:47353` 的场景、尺寸和视觉样式不一致；组件默认行高、表头背景、列宽策略、排序图标、固定列分隔和加载/选择控件也没有完整使用 TDesign 视觉语义。小程序 Table 已提供行点击、单元格点击和横向滚动等交互，Flutter 仅暴露单元格点击，公开交互能力尚未收敛。

## 范围与非目标

### 目标

- 公开 Demo 覆盖 Figma 中的基础、排序、文字操作、图标操作、固定首列、固定尾列、横向滚动、斑马纹和边框场景。
- 组件默认尺寸、颜色、文字、排序指示和固定列边界对齐设计稿，并支持未指定列宽时自动均分可用空间。
- 保留强类型列定义和受控排序/选择，补齐行点击事件，并让边框、斑马纹可以在组件实例上显式配置。
- 对齐小程序可见操作模式，同时保持 Flutter 的 Widget 构建器、受控状态和滚动通知惯例。
- 建立组件、Demo 交互和视觉回归门禁，并输出修复前后截图差异标注。

### 涉及

- `TTable`、`TTableColumn`、`TTableThemeData` 的默认视觉、布局和事件契约。
- Table 公开 Demo 的结构、文案、数据、操作和样式。
- Table 组件测试、Demo 测试、Golden 测试及测试清单登记。
- 公开 API dartdoc、Spec 和生成产物验证。

### 不涉及

- 不机械复制小程序的 WXML 属性或事件命名。
- 不在本次引入固定行、服务端排序或虚拟化数据源。
- 不改变受控选择和受控排序的状态所有权。
- 不手工维护脚本生成的 API、示例代码或 CHANGELOG 产物。

- Table 之外组件的视觉或 API 调整。
- 小程序仓库代码修改。
- Figma 文件内容修改。

## 最终方案与行为契约

- `TTableColumn.width == null` 时，所有未指定宽度的列在扣除选择列、固定显式宽度列和滚动显式宽度列后均分当前表格可用宽度；显式宽度列保持指定宽度并在超出中间区域时横向滚动。
- `TTableColumn.minWidth` 是列宽下限；自动列先满足各自最小宽度，再均分剩余空间，总宽超出表格时由中间区域横向滚动。
- `TTable.bordered`、`TTable.stripe` 采用实例值优先、`TTableThemeData` 次之、组件默认值最后的优先级。
- 默认表头和数据行高度为 38，表头背景使用容器色；表头文字使用占位色，数据文字使用主文字色，单元格水平内边距由当前全局尺寸刻度回退，默认 12dp。
- 可排序列展示上下双向指示，点击依次请求升序、降序、未排序；组件不在内部持有排序状态。
- 固定首列或尾列与滚动区之间显示稳定分界，横向滚动时表头和各数据行保持同一偏移。
- `onCellTap` 通过 `TTableCellContext` 返回行索引、列索引、行数据和列；`onRowTap` 返回行索引和行数据。点击单元格时同时满足单元格与行级事件语义，保持与小程序事件冒泡模式相近。
- `rowKey` 为空时继续使用行对象自身的相等性；提供时以返回的唯一 key 识别受控选中行，使数据对象重建后仍能命中同一业务行。
- `cellSpanBuilder` 在未被其他合并区域覆盖的逻辑单元格上返回 `TTableCellSpan`；跨度必须为正、不得越界、不得重叠，也不得跨越左固定区、水平滚动区和右固定区。被覆盖坐标不再单独构建，整个合并区域按起点单元格响应点击。
- `height` 固定整个 Table 的高度，表头和 footer 占用固定高度后的剩余空间作为表体滚动视口；`height` 与只约束表体的 `maxHeight` 互斥。
- 选择、排序均基于当前受控输入；禁用行不进入全选结果。
- 加载和选择默认视图使用 TDesign 组件，不直接泄漏 Material 默认视觉。

## 关键决策与取舍

| 决策 | 理由与取舍 |
| --- | --- |
| 采用的方案 | 自动列先满足 minWidth 再分配余量，固定区与滚动区共享偏移；合并区域不得跨越分区。 |
| 保留的边界与代价 | 排序和选择由调用方控制，rowKey 为重建后的业务行提供稳定身份；height 与 maxHeight 各有明确范围且互斥。 |

### 设计演变中的关键理由

- 自动均分改变未显式设置列宽时的默认布局，属于有意的 breaking change；显式宽度可恢复旧的固定宽度行为。
- 合并单元格与固定列共存时只允许在同一固定区域内合并；跨区合并语义不明确且无法保持独立滚动，因此作为无效配置拒绝。
- 合并单元格需要跨行布局，表体改为一个共享纵向视口和一个中心横向视口；表头继续与中心表体同步横向偏移。
- 本机截图只作为人工比对证据；仓库 Golden 只在规定 Linux/Flutter/字体环境生成和验收。

## 兼容性与迁移

- `TTableColumn.width` 从非空 `double` 改为可空 `double?`，默认值由固定 120 改为自动均分。这是公开签名和默认布局行为变更，按 breaking change 记录。
- 新增可选参数 `bordered`、`stripe` 和 `onRowTap`，不影响现有调用。
- 新增可选参数 `rowKey`、`cellSpanBuilder`、`height` 和 `TTableColumn.minWidth`，未配置时保持原行为。
- `onCellTap` 从三个位置参数收敛为一个 `TTableCellContext<T>`，属于公开回调签名的 breaking change；调用方迁移为从 context 读取 `rowIndex`、`columnIndex`、`row` 和 `column`。
- 显式传入列宽或 ThemeData 样式的现有调用保持原有控制能力。

## 验收标准

- 公开 Demo 的标题、描述、分组、场景顺序和 10 行数据与 Figma 对齐。
- 默认 4 列表格在 375 宽度内均分，表头加 10 行总高为 418。
- 排序三态、行/单元格点击、选择、固定列和横向滚动有自动化测试。
- 斑马纹和边框由 `TTable` 实例 API 配置，Theme 仍可作为子树默认值。
- Figma、修复前和修复后截图形成可追溯的标注对比。
- Flutter 3.32.0 与 latest 的测试、analyze 通过，Golden 在规定 Linux 环境复跑无差异。
- 行 key、列最小宽度、固定高度、单元格上下文与合法/非法合并矩阵有聚焦测试。
- 合并、列最小宽度与固定列、固定高度与 footer 具有 light/dark 组件 Golden；无独立视觉状态的行 key、上下文和异常契约由 Widget 测试覆盖。
- 新 API dartdoc 与生成 API 文档完整描述默认值、限制条件和迁移方式。
