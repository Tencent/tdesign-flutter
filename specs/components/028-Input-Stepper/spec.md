# Stepper 设计说明

## 背景与目标

以下保留设计形成时的问题与依据；已修复的问题不表示当前代码仍有同一缺陷。

边界草稿、受控拒绝和字体度量会造成数值与行盒不一致。

## 范围与非目标

### 目标

以 Figma `mdBVCCVGERhxoZLle2eLT0 / 28591:40152` 为展示目标，修复基础、边界、禁用、形态与尺寸示例，并建立独立行为与视觉回归。小程序仅作为 API 和交互参考；设计稿已删除的中间边界示例不再保留。

## 最终方案与行为契约

### API Review

- `value + onChanged` 为严格受控模式；`onChanged == null` 表示整组禁用，不引入 `defaultValue` 或重复的 `disabled`。
- `min/max/step` 负责数值约束，`TStepperVariant` 与 `TStepperSize` 负责互斥视觉语义。
- `variant/size` 由实例参数选择，未设置时分别回退 normal/medium；组件 Theme 不提供同义状态字段，无需复制小程序字符串 API。
- 保持现有公开构造参数、枚举和默认值，不新增小程序专属参数。修复编辑草稿与按钮可用状态、nullable Theme 插值；属于既有契约修复，不删除能力或修改公开签名。

- Demo 保持三个分组、五个代码入口，共十个步进器；边界只展示 0 / 999，禁用值为 0。基础与禁用左对齐，各块使用完整宽度、组件容器底色和 16px 内边距。
- 最小/最大状态分别由受控值等于边界表达，禁用由空 callback 表达。
- 所有可交互实例由各自 StatefulWidget 示例持有状态，主题切换、代码模式切换和页面重建不重置编辑后的值。
- 五个面板展示实际运行的示例 Widget、对应 State 和依赖导入；页面壳不进入片段。生成器沿用 ExampleCode 注解，支持独立 Widget 及同文件直接关联 State 的提取，不添加示例框架参数。
- 编辑期间按钮启停和步进运算使用同一个有效草稿值；合法草稿即使从边界开始编辑，也可向两个方向步进。父组件仍为唯一提交值源，拒绝请求时回退，单次操作最多通知一次。
- Theme 双侧 null 保持继承；单侧 null 按组件当前生效的尺寸、TStepperThemeData 和 TD token/内置默认解析后插值，不当作 0 或透明色。插值端点保持原始配置，动态主题和实例尺寸覆盖路径均须验证。
- 数字输入区按小、中、大尺寸分别使用 10/16、12/20、16/24 字号与行盒，行盒在控件内垂直居中；未显式配置字体时使用 TDesign 数字字体，仅由 `TStepperThemeData.textStyle` 覆盖内置字体，不读取外部 `DefaultTextStyle`。字体族与 package 必须按同一来源解析：组件 Theme 的无 package 字体不得继承底层字体的 package，组件 Theme 仅覆盖字号时保留 TD 数字字体，不继承外部字体或 package。组件 Theme 仅覆盖字号时，默认物理行盒按最终字号重新计算倍数，并在自定义控件高度更小时收敛到可用高度；显式 `TextStyle.height` 仍具有最高优先级。最终字号大于控件高度，或显式字号与行高形成的物理行盒大于控件高度时属于无效配置，调试模式必须给出包含最终尺寸的断言，避免静默裁字或光标溢出。

## 关键决策与取舍

| 决策 | 理由与取舍 |
| --- | --- |
| 采用的方案 | 父级拥有最终值，编辑草稿与合法提交分开；字体先解析最终字号和控件高度再计算行盒。 |
| 保留的边界与代价 | 保留现有构造与默认值，采用一致的数字字体及完整字体族解析，避免平台度量和 package 继承污染。 |

### 设计演变中的关键理由

代码模式应保持同一 StatefulWidget 子树，避免切换遮罩重置草稿；字体族先解析完整 package，再合并组件 Theme，避免私有 package 污染。

- 行为覆盖：两端边界草稿、父组件接受/拒绝、非法草稿、即时按钮边界更新；主题双向插值、端点、实例尺寸、继承主题、TD token、copyWith、嵌套插值及 AnimatedTheme。

- 新增组件契约测试、生成器测试和四张视觉回归的 CI 入口登记；GitHub/CNB 工具入口同步。

- Figma 组件源节点确认小、中、大号数字规格分别为 10/16、12/20、16/24，文字行盒在控件内垂直居中；Form 的 `年限` 项没有额外位移。

- Theme 回归复核发现，先按默认 12px 字号写入 20px 行盒倍数、再仅覆盖字号为 20px 时，会得到约 33px 的错误行盒；仅覆盖控件高度为 16px 时，默认 20px 行盒也会超出可用高度。修复后先解析最终字号和控件高度，再计算默认行盒倍数；20px 自定义字号保持 20px 行盒，16px 自定义控件高度下行盒收敛为 16px，显式行高覆盖保持不变。20px 字号与 16px 控件高度、12px 字号与 2 倍显式行高及 20px 控件高度等冲突组合会在调试模式明确断言，不再把无法容纳的配置视为有效布局。
