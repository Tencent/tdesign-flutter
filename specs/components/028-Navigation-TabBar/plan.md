# TabBar 实施方案

## 实现组织

标签项、徽标和多级菜单共享组件内布局与定位；胶囊阴影和圆角由组件解析。

保留真实弹层生命周期与点击边界，不用 Demo 位移或虚假的命中区替代。

| 范围 | 实际入口 | 维护要求 |
| --- | --- | --- |
| 生产实现 | [tdesign-component/lib/src/components/tabbar](../../../tdesign-component/lib/src/components/tabbar) | 按 spec.md 的最终方案维护配置、状态和布局 |
| 测试与消费者 | [tdesign-component/test/components/tabbar](../../../tdesign-component/test/components/tabbar) | 对默认、覆盖、重建和直接组合消费者补充真实断言 |

## 实施顺序与验证

1. 先明确最终方案、接口变化与调用方边界；新增设计决策回写 spec.md。
2. 同步实现、公开注释、消费示例和测试；生成物只从源码生成。
3. 围绕该职责的默认、显式配置、状态变化、异常与生命周期做真实验证；按适用范围执行双 SDK、Golden、设备或交付检查。
4. 结果绑定候选、环境和必要证据，更新 acceptance.md；真实剩余工作只在 tasks.md 维护。

此前文档整理不代表实现验收；本轮文字槽实现与本地验证见后文和 acceptance.md，不据旧命令流水推定当前检查通过。

## 文字槽一致性

复用内置菜单文案的解析结果提供 TTextStyleScope；不更改全局 TText。回归覆盖原生/TText、布局包装、显式样式、内部局部主题、明暗、文字缩放及各自状态/布局边界。双版本功能检查通过后运行已有视觉入口，前后截图用于独立审阅，不放入 Spec；已有基线变化须逐项审阅。

新增自定义菜单长文案、混合等高、超屏滚动的明暗视觉回归；通过真实点击/滚动触发，沿用现有字体和视觉登记入口，只新增基线文件，不改正式 Demo 或已有 PNG。

## 菜单回调路由修复

两种布局复用私有 _selectItem；保留先通知后关闭。仅针对原菜单选择跳过、pop 或 removeRoute。使用旧 API 独立于命名迁移，按组件 CI 清单运行双 SDK 功能与覆盖率、字体和生成文档检查。
