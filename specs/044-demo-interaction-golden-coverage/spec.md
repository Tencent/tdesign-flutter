# Demo 交互 Golden 完整性

## 背景

现有组件视觉回归已经覆盖每个已登记组件的初始 Demo 页面，但交互后状态的覆盖不一致：部分弹层组件已经保存打开态，部分可选择、可展开、可输入组件仍只有初始态。Demo 优化可能因此改变操作后的稳定视觉而不触发 Golden 失败。

## 目标

- 以公开 `ExampleItem` 为边界，审计所有已登记组件的稳定可见状态。
- 初始页面以及点击、展开、选择、输入、滚动等产生实质视觉差异的稳定状态均有 light/dark Golden。
- 按压、展开过渡等动画可在受控时间点保存可复现的中间帧。
- 交互场景与视觉回归调度清单可被自动检查，避免新增测试文件但未进入 CI。

## 非目标

- 不修改组件实现、公开 API、默认样式或 Demo 展示内容。
- 不为仅回调、无视觉差异的操作复制相同快照。
- 不把持续循环、网络、系统时间等不可确定状态直接写入基线。
- 不在 macOS 上生成或更新权威 Golden。

## 范围

### 涉及

- `tdesign-component/example/test/` 中的 Demo Golden、共享测试工具和基线。
- `tdesign-component/tool/demo_golden_coverage.dart` 及视觉回归调度器自测。
- 所有已登记组件的公开 Demo 场景覆盖矩阵。

### 不涉及

- `tdesign-component/lib/` 下的组件生产实现。
- 未进入公开 Demo 的测试专用状态。
- 组件 API 文档和更新日志。

## 行为契约

1. 每个已登记组件至少保留初始公开页面的 light/dark Golden。
2. 真实操作后出现且能稳定停留的视觉状态必须通过真实手势触发，并分别保存 light/dark Golden。
3. 瞬时动画只在其视觉本身属于组件契约时保存；测试先创建并保持手势或精确 `pump` 到指定时点，不使用 `pumpAndSettle` 跳过动画。
4. 无限动画、平台纹理、系统输入法或仅回调结果由功能测试负责，并在覆盖矩阵说明不截图原因。
5. Golden 更新只在 Linux Flutter 3.32.0 环境进行，更新后使用相同命令无更新参数复跑。
6. 新增的视觉测试必须登记到对应组件的 `visualTests`，功能断言仍由双版本 example regression 执行。

## 验收标准

- [x] `tool/components.json` 中 57 个公开 API 组件均有明确的初始态与交互态分类。
- [x] 所有存在稳定视觉变化的公开交互均有真实触发后的 light/dark Golden，或有可审计的等价覆盖说明。
- [x] Button 按压态以保持手势的方式固定，不依赖随机动画帧。
- [x] 展开/弹层类状态在完成过渡后截图；需要验证过渡本身时另存固定时点帧。
- [x] 调度器自测、example 功能测试、Linux 视觉回归及严格 analyze 通过。
- [x] 未修改组件生产代码、公开 API 和 Demo 默认视觉。
