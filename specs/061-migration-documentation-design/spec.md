# 0.2.7 → 1.0 迁移文档设计

状态：设计完成，站点和指南结构改造尚未实施。日期：2026-10-15。

## 背景

现有根目录 `MIGRATION_1_0.md` 已有通用迁移说明、57 项组件入口索引和383 项旧公开声明处置索引，但还没有57 个可直接定位的组件专章。组件页面目前只保留生成示例和 API 入口；页面契约明确禁止手写迁移段落。

## 目标

采用“一份完整指南 + 组件页面自动生成的简短入口”。用户既能按升级顺序阅读，也能从当前组件页直接找到旧 API 的迁移方法。范围仅为0.2.7 到1.0，不包括 alpha 之间迁移。

## 范围与非目标

本次交付信息架构、页面文案样稿、57 项入口映射、维护方式与实施验收清单。后续实施才调整根指南、同步逻辑和站点渲染。组件实现、CI、测试调度清单、版本号与自动 CHANGELOG 不属于本设计改动范围。

## 行为契约

1. 根目录指南是迁移正文的唯一维护来源；包内和站点指南由现有同步脚本产生。
2. 每个组件有稳定英文锚点 `migration-<站点组件slug>`，例如 `migration-tab-bar`。标题更名不改变链接。
3. 组件页在“代码演示”之前展示“从 0.2.7 升级”普通提示块：旧入口、新入口、最多三条关键变化、完整指南链接。不使用弹窗，不阻塞首次访问。
4. 摘要从指南中对应组件章节提取；不得在57 个 README 内复制迁移正文或代码。
5. 迁移指南提供到当前组件页的返回链接。仓库和包内阅读使用指南内部锚点；站点入口使用 `/flutter/migration-1-0#...`，不能把站点绝对路由复制到离线说明的内部目录。
6. FAQ 只解释常见困惑，并链接到具体迁移章节；不承担完整替换清单。
7. 未完成证据、待确定的默认视觉或能力处置不得写成“已验证”或“无需调整”；文档完成也不表示1.0 发布验收完成。

## 验收标准

- 57 个现有索引项都有唯一组件章节、有效组件页面和往返链接；特殊命名有显式映射。
- 全部旧公开声明都能定位到具体处置说明；无法自动替换的类型写清替代组合或能力边界。
- 每个组件章包含迁移对照、示例、行为差异、移除能力及检查清单；不适用项有原因。
- 组件页摘要与指南同步，重复锚点、缺失摘要、无效目标均阻断文档生成。
- 旧代码在0.2.7 环境验证，新代码在最低和当前稳定 SDK 验证；新旧代码分环境，不混用依赖。
- 站点构建、既有页面契约和示例/API 校验通过；桌面及窄屏真实跳转验证通过。
