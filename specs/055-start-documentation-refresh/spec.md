# 入门与全局配置文档及示例一致性项目

## 背景与目标

用户需要先跑通应用，再按需求理解应用主题、组件默认值、局部覆盖和实例参数。此前教程与预览采用不同组件，展示方式和验收记录随局部修补累积，无法作为一个整体检查。

## 范围

中英文 README 与生成的快速开始、贡献指南、自定义主题、深色模式、国际化、对应菜单和跨页锚点；两个真实 Flutter 示例、生成源码和正文 Web 预览；共享契约检查与回归测试。沿用一个隔离分支和 PR。

不修改组件库公开 API、默认行为或 57 个组件页的生成正文，不引入国际化交互演示或无关工作区改动。无 breaking change。

## 用户任务与交付契约

| 用户任务 | 文档入口 | 可验证结果 |
| --- | --- | --- |
| 运行第一个应用 | 快速开始 | 完整最小应用，实际 TNavBar 与 TButton，按需求进入全局配置 |
| 配置样式作用范围 | 自定义主题 | 同一组实际 Button 展示品牌色、全局圆角、组件图标间距、局部圆角与实例尺寸 |
| 选择明暗模式 | 深色模式 | 实际 TD 按钮展示浅色、深色、跟随系统，说明业务持久化边界 |
| 切换语言 | 国际化 | 注册、选择、扩展三步，公开接口来自实际代码 |
| 贡献改动 | 贡献指南 | 按改动类型选择验证入口，规范和生成流程链接到唯一来源 |

教程中的核心配置解释必须对应预览源码。源码只从 Example App 生成，不能维护另一份演示代码。预览位于正文流内，宽度随容器收缩；不遮挡标题和正文，按钮保持自然宽度并提供真实点击反馈。局部覆盖保留品牌色和组件扩展。

构建必须拒绝缺失或重复预览挂载点、未知或错误路由、错配源码、无效预览高度。组件页面继续遵守生成正文契约。

## 验收标准

1. 阅读路径和文档/源码/路由对应关系完成整体审查。
2. 生成产物与源码一致，站点契约测试和生产构建通过。
3. Flutter 3.32.0 和本地高版本分析及交互回归通过；远程 latest 由 CI 验证。
4. 浏览器验证宽窄屏、模式切换、品牌色、全局/局部圆角、组件间距和按钮反馈。
5. 同一 PR 的最终远程 head 与检查状态确认，未完成项明确登记，不将历史证据当成最终验收。
