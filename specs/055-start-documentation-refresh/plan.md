# 实施方案

## 技术方案

1. 官网贡献指南保留开发、Issue 协作和自测路径；规范统一链接根目录 CONTRIBUTING、Spec 和 PR 模板，删除旧二进制配置说明。
2. 中英文 README 增加完整最小应用与当前 ThemeExtension 用法，国际化链接已有完整代理而非不完整具体类。
3. 中文 README 用显式标记界定接入内容，同步脚本先计算并验证所有目标，再写入；通过临时夹具验证真实 CLI 行为。

## 影响范围

| 范围 | 文件或模块 | 影响 |
| --- | --- | --- |
| 文档 | README.md、README_zh_CN.md、tdesign-site/CONTRIBUTING.md | 当前接入与贡献说明 |
| 工具 | scripts/sync-readme.mjs | 官网输出范围与失败行为 |
| 测试 | scripts/sync-readme.test.mjs | 真实同步、幂等与失败原子性 |
| 生成产物 | 组件包 README、官网 getting-started.md | 由同步脚本更新 |

## API 变化

无组件 API 变化，无 breaking change。

## 风险与取舍

官网不再完整复制 README；接入信息仍只有中文 README 一个来源，项目介绍继续保留在仓库和 pub 包 README。标记契约以失败显式暴露源文档错误，避免输出空页或误删内容。

## 验证策略

执行同步 CLI 测试、README 同步与幂等检查、站点构建、文档 Dart 示例双版本分析和页面渲染检查。记录阻塞或已有告警，不扩展到组件修复。

## 按用户任务收敛（后续调整）

快速开始减少为环境/依赖、完整应用和需求导航。主题详细内容迁移到自定义主题教程，深色模式集中模式选择和持久化，国际化提供独立接入说明。全局配置菜单启用这三个说明页，原 Theme 组件页继续只包含生成示例/API，菜单名称改为 Theme API。

中文 README 中新增 `自定义主题` 锚点兼容原 FAQ 的入口，定位到需求导航，不重复详细内容。验证覆盖新路由、需求入口、旧锚点、已迁移的 Dart 示例及资源代理注入。

官网生成时将 TDesign Flutter 文档链接转换为站内路径，保留锚点，避免预览或其他部署环境点击后跳到生产站；仓库及组件包 README 保留绝对地址。Theme API 仅修改 front matter 标题以匹配菜单，正文保持生成契约。

## 阅读成本优化

贡献指南隐藏生成器内部实现，按文档、组件、视觉与平台能力选择验证步骤；国际化合并为配置资源、实现代理、注册代理三步；自定义主题删除重复解释并明确快速开始的替换位置。中英文需求导航缩为两列，主题需求直接定位小节。保留所有 Dart 示例和接入行为提醒，仅调整说明与导航；同步、站点构建和浏览器定位重新验证。

浏览器发现跨页导航首次加载时没有定位 URL 锚点；在文档内容加载完成后定位对应元素，覆盖跨页入口和直接打开链接，兼容旧主题锚点。
