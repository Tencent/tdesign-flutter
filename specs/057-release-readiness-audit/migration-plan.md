# 0.2.7 → 1.0 迁移说明方案（不实施）

## 范围与交付

仅覆盖 0.2.7 使用方升级到正式 1.0；不提供 alpha 迁移章节、不要求先升级 alpha。

建议正式交付为根目录 MIGRATION_1_0.md（唯一正文），在包 README、站点快速开始和 1.0 发布说明放入口；包发布时包含该正文，站点从唯一正文同步展示，避免复制后分叉。站点导航是否单独增加迁移页按现有文档配置接入。此次仅提出位置与结构，不创建指南或修改导航。

比较起点固定本仓库 tag 0.2.7；终点先用 develop@30767a55 盘点，发布时替换为最终 RC/1.0 tag 并重新比对。pub.dev 已发布 0.2.7 的包内容应与 tag 对照，若不一致，使用实际发布包作为用户契约来源。

## 编写步骤

1. 从两个版本的公开包入口追踪导出，列出类、构造参数、枚举、回调、Controller、Theme 和顶层函数的新增/删除/改名/类型变化；内部文件变化不直接进入用户清单。
2. 对每项标注：可机械替换、需业务改写、默认行为变化、能力删除无等价替代。分别记录旧调用、新入口、迁移理由、默认值/空值变化和验收用例。
3. 按组件汇总，优先处理主题与文字、按钮与输入、受控选择、Popup/Dialog/Picker 组合、Controller/Overlay 生命周期和 Upload。先写公共规则，再链接组件具体行，减少重复。
4. 为高频调用提供前后代码，旧例在 0.2.7 的独立宿主验证，新例只导入公开包入口，在 Flutter 3.32.0 与当前 stable 验证；旧版不兼容最新 SDK 时在其兼容 SDK 留下旧例证据，不将旧版兼容性误算为新版本失败。
5. 新例复用并扩展现有仓库外 consumer 机制；每组标注覆盖的迁移条目 ID。编译检查之外补受控值、禁用态、回调、打开/关闭与释放等关键行为验证。
6. 最终 RC 固定后检查指南的每个替代入口仍公开可用；正式包发布后用 pub.dev 依赖安装验证，不只依赖仓库 path。

## 建议目录

- 升级前准备：Flutter/Dart 最低版本、备份依赖与基线截图。
- 公共变化：TD 前缀、图标包、单入口 Material 导出、主题/字体与局部覆盖。
- 组件迁移索引：按基础、导航、输入、展示、反馈分组。
- 复杂组合：Popup/Picker/DateTimePicker/Dialog、Calendar/Cascader、Swiper。
- 行为变化：受控状态、禁用条件、回调时机、Controller 释放、Overlay context、深色/字体/安全区。
- 删除能力与替代组合：明确无等价替代，避免承诺全部旧能力保留。
- 升级验收清单与常见编译错误索引。

## 已确认不能机械改名的示例

0.2.7 的 TDButton 有 text、type、theme、disabled、onTap、icon/iconWidget 及分状态 style；当前 TButton 使用 child、variant、colorPreset、onPressed、Widget icon 与 ButtonStyle，onPressed 为 null 表示禁用。只把 TDButton 改成 TButton 无法完成迁移。指南应把相关参数放在同一组迁移，不能独立替换后遗漏禁用和回调语义。

主题迁移资料只能作为盘点来源。Spec 011 的旧 migration.md 仍包含 TText.fontFamily、Material Theme/DefaultTextStyle 自动默认等历史用法，已被后续收敛覆盖；Spec 048 的“相对 develop”是阶段性比较，不是完整 0.2.7 → 1.0 证明。编写时必须用当前源码确认每条，不能拼接成最终指南。

## 完成标准

全部公开 breaking diff 均有迁移条目或明确的“无替代”；所有新代码可通过公开入口编译；关键行为通过双版本 consumer；指南、包和站点同版本；尚未验证的条目不得写成可直接复制的建议。
