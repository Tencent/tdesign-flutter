# API 文档统一展示与逐组件验收规则

## 范围与事实源

维护者已授权以 Popup 候选为基准推广至 manifest 的全部 57 个组件。公开 dartdoc 是内容来源，生成器维护统一展示，manifest 维护公开声明归属。修复错误或缺失注释时对照实际实现；不为匹配文档改变组件实现、公开 API、默认值或 Demo 使用方式。示例页面补充与类型跳转仍暂缓，源码中的已有示例保留，但 API 页不重复展示。

## 展示规则

| 项目 | 规则 |
| --- | --- |
| 页面开场 | 仅保留 API 标题，不添加表格阅读指南或系统性总述 |
| 类型 | 三级标题为实际公开类型名；紧接简短用途，不重复「简介」「声明」 |
| 构造 | 四级「构造方法」；五级实际名称，默认构造在前，命名构造按名称排序 |
| 成员 | 属性、静态成员、静态/实例方法分组按实际存在情况输出，保留用户语义成员 |
| 方法 | 五级实际名称；必要短说明、参数表、六级返回值分组；无参明确说明，无返回值不生成空表 |
| 标题归属 | 注释标题不越过所属 API；相对层级保留，超过六级以加粗段落表示 |
| 全部表格 | 名称、类型、默认值、说明、必传；不适用项用 `-` |
| 输入参数 | 类型、源码声明默认值和 required 状态来自 AST；位置参数保留顺序，泛型保留约束 |
| 返回值 | 类型来自 AST，说明来自源码「返回值」段落；不能从类型猜测行为 |
| 回调 typedef | 四级回调参数和返回值表；参数顺序、类型、必传、泛型、可空性均保留，void 回调显式展示 void 返回 |
| 其他 typedef | 类型定义表保留目标类型和泛型契约 |
| 枚举和关系 | 枚举完整列出；有意义的状态/配置组合以五列说明表表达，单一行为用短说明 |
| 去重与精简 | 去掉完整签名、const 标识、API 示例代码及孤立示例标题；去掉内部实现叙述和重复阅读指引 |

## 内容规则

- 字段说明交代用途、运行时回退、null 语义、生效条件及必要关联；源码声明默认值与运行时默认值分别表达。
- 受控与非受控状态、Controller 的持有/释放、回调触发条件、Future 返回时机、重复调用与异常行为按实现记录；不能将开始、结果返回和动画结束混为一谈。
- 布局说明交代尺寸约束、头部/尾部/插槽占位、安全区与滚动责任；不将 Demo 的布局当成组件能力。
- Theme 的实例覆盖、字段级回退、动态更新或创建时快照按各组件实现记录，不机械复制 Popup 的规则。
- 组合表保留真实互斥、依赖和无效组合，不能只保留字段名称；用户无需拼接多个片段才能推导核心行为。
- 公开方法和回调返回说明必须准确；返回 void 的普通方法不增加无意义表格。既有实现问题独立报告，不以注释修复掩盖。

## 逐组件流程与证据

1. 阅读该组件的公开类型、实现与当前注释，核对用途、参数、Theme、布局、状态和生命周期。
2. 只修必要的源码 dartdoc；使用候选工具按 manifest 生成该组件，核对完整产物和标题归属。
3. 校验每个构造/方法/typedef 的 AST 契约、表格列、声明/示例清理和返回说明；修复后重新生成同一组件。
4. 记录该组件的具体发现、修复及暂缓事项；不能用「注释非空」或校验成功替代内容结论。
5. 全部组件分别执行双 SDK 生成/validate，确认字节一致、幂等、运行 token 与公开契约不变。共享生成器有变化时重跑完整工具回归。
6. 两版真实 Flutter API 页面逐组件加载；官网构建后逐页核对实际标题、表格和类型归属，保存结果。必要的业务行为疑点用现有定向测试或临时验证澄清。
7. 输出组件源码注释、运行实现、Demo 使用方式和工具改动的分项影响报告。正式工具 ref、推送/远端 CI 和示例/跳转的状态单独记录。

本轮验收仅涵盖 API 文档；不据此宣称组件设计、全部 Demo 交互或 Golden 完整通过。

## 语义合理性复核补充（2026-10-08）

结构生成不等于文档合理。逐组件至少核对：null/未传语义、Future 完成时机、controller/Navigator/Overlay 所有权、Theme/Token 回退或快照、布局尺寸/滚动/安全区责任。测试通过只能证明测试断言描述的行为；如果文档写强了，测试可能正好证明文档错误。必须区分实现事实、测试证据、文档结论和实现风险。
