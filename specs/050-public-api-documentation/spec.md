# 公开 API 文档完整性

## 背景

manifest 遗留过期名称和缺失 Theme；工具遗漏普通实例方法及访问器；源码存在缺注释项。

## 目标

每个组件展示当前公开构造函数、字段、访问器、方法、控制器、枚举、typedef、Theme 与公开扩展。注释从实现修复，Markdown 从源码生成。

## 非目标

改变组件 API、默认行为或视觉；公开内部实现；复制维护参数表。

## 范围

组件源码 dartdoc、API manifest、检查脚本、Demo API assets、生成器独立工具仓库、CI 与工具说明。

## 行为契约

- 公开范围以 lib/tdesign_flutter.dart 的本仓库导出为准，处理 part、转导出、show/hide。
- @internal、@visibleForTesting 及 Flutter/Object 标准无用户语义方法不进入用户文档。
- 构造声明默认值与运行时 Theme/token 回退分别描述；不能把 null 替换为推测默认值。
- 普通控制器和句柄的方法、访问器与命名/无参构造不得遗漏。
- 自定义 ThemeExtension 的 copyWith/lerp 和 Token 查询运算符具有用户语义，必须补注释并展示；仅排除标准框架生命周期钩子。
- API 页不展示独立的类/extension「声明」章节；类型参数及 extension 适用类型用简短说明保留。构造、方法、顶层函数的调用签名和 typedef 定义仍展示泛型约束、位置/命名参数、默认值与必填状态。
- API 页的简介、构造与方法正文不展示完整示例代码和孤立示例标题，保留用途、默认值、空值、约束、回调、返回值和异常；源码 dartdoc 及专门示例页的示例保留。参数说明不得仅凭同名字段或参数名推断。
- 检查器逐可调用声明比对参数清单与表格，并校验调用签名和类型参数；缺参数、错误类型/默认值/必填状态、重复行及转义竖线不得漏检。
- 全量内容验收逐组件对照运行实现；构造参数的短说明不能遮盖字段的完整契约。多行参数说明与 dartdoc 引用必须完整保留。
- 每个组件记录默认值、空值、生效条件、参数关系、回调和生命周期及 Theme 回退；结构检查不得替代语义审查。
- 最终报告区分组件源码注释、运行实现、Demo 使用方式和文档工具修改；以 Token 与签名比对确认实际 API/行为影响。
- Demo 的注册路由名与资产 slug 不同（如 backtop / back-top）时，从真实 AssetManifest 按归一化名称匹配 API 文件；API 路由的 canonical slug 和既有注册名均指向同一页面。未知文档返回空提示，不复用之前的组件文档。
- manifest 只描述归属；API 文本只能从源码生成。
- 独立工具修复单独交付，最终生成使用消费仓库正式 ref，不提交临时 path override。
