# 公开 API 文档完整性

## 背景

manifest 遗留过期名称和缺失 Theme；工具遗漏普通实例方法及访问器；源码存在缺注释项。

## 目标

每个组件展示当前公开构造函数、字段、访问器、方法、控制器、枚举、typedef、Theme 与公开扩展。注释从实现修复，Markdown 从源码生成。

## 非目标

改变组件 API、默认行为或视觉；公开内部实现；复制维护参数表。

## 范围

组件源码 dartdoc、API manifest、检查脚本、Demo API assets、生成器独立工具仓库、CI 与工具说明。

## 行为契约

- 公开范围以 lib/tdesign_flutter.dart 的本仓库导出为准，处理 part、转导出、show/hide。
- @internal、@visibleForTesting 及 Flutter/Object 标准无用户语义方法不进入用户文档。
- 构造声明默认值与运行时 Theme/token 回退分别描述；不能把 null 替换为推测默认值。
- 普通控制器和句柄的方法、访问器与命名/无参构造不得遗漏。
- 自定义 ThemeExtension 的 copyWith/lerp 和 Token 查询运算符具有用户语义，必须补注释并展示；仅排除标准框架生命周期钩子。
- API 页不展示独立的类/extension「声明」章节；类型参数及 extension 适用类型用简短说明保留。全部构造、静态/实例方法和顶层函数统一展示名称、参数表、返回类型和行为说明，不重复完整签名代码或 const 标识；位置参数另列传入顺序，其他参数默认按名称传入，方法泛型用「类型参数」保留约束。typedef 的类型契约以表格保留，不重复源码声明；参数类型、默认值、必填状态与泛型约束不得丢失。
- API 页的简介、构造与方法正文不展示完整示例代码和孤立示例标题，保留用途、默认值、空值、约束、回调、返回值和异常；源码 dartdoc 及专门示例页的示例保留。参数说明不得仅凭同名字段或参数名推断。
- 所有构造、方法及顶层函数的参数表仅使用「名称、类型、默认值、说明、必传」五列；名称统一表示参数名，必传保持源码 required 语义。校验兼容旧「参数/必填」及新「名称/必传」表头，不削弱参数契约检查。
- API 页不增加统一的表格阅读规则或参数传入规则开场说明；默认值/必填由表格表达，位置参数顺序与运行时回退在所属 API 的必要说明中保留。
- 类型说明直接置于类型名下，不生成重复的「简介」标题。渲染时按说明所属层级重排 Markdown 标题：类型说明从四级开始，顶层函数说明从五级开始，全部构造/方法说明从六级开始；保留相对层级，超出 Markdown 六级的子标题使用加粗段落，不允许注释标题越过所属 API。Popup 试点确认后推广至 manifest 全部 57 个组件；说明章节的语义与归属在各组件源码 dartdoc 维护。
- 类型下按用途说明、必要使用说明、构造方法、属性/静态成员、静态/实例方法组织；仅输出实际存在的分组。所有构造统一归入四级「构造方法」，默认构造与命名构造均以实际名称使用五级标题，默认构造在前，命名构造按名称排序；参数表直接置于说明下，不增加重复「参数」标题。「属性」不附加字段/访问器实现术语。使用说明子标题使用五级。校验器同时接受既有资产与新分组，不能把相邻构造或方法的参数混入。
- 检查器逐可调用声明比对参数清单与表格，并校验所有可调用 API 的位置参数顺序、方法泛型约束、返回类型与类型参数；缺参数、错误类型/默认值/必填状态、重复行及转义竖线不得漏检。
- 全量内容验收逐组件对照运行实现；构造参数的短说明不能遮盖字段的完整契约。多行参数说明与 dartdoc 引用必须完整保留。
- 每个组件记录默认值、空值、生效条件、参数关系、回调和生命周期及 Theme 回退；结构检查不得替代语义审查。
- 最终报告区分组件源码注释、运行实现、Demo 使用方式和文档工具修改；以 Token 与签名比对确认实际 API/行为影响。
- Demo 的注册路由名与资产 slug 不同（如 backtop / back-top）时，从真实 AssetManifest 按归一化名称匹配 API 文件；API 路由的 canonical slug 和既有注册名均指向同一页面。未知文档返回空提示，不复用之前的组件文档。
- manifest 只描述归属；API 文本只能从源码生成。
- 独立工具修复单独交付，最终生成使用消费仓库正式 ref，不提交临时 path override。

- Popup 类型用途保留一句；删除重复构造推荐、内部实现叙述和阅读指引。方向与构造关系、蒙层组合、开关状态等并列行为以表格呈现；具体字段限制与空值语义放在字段/参数说明，不以表格压缩为由丢失契约。只修源码 dartdoc 并逐组件生成，运行 token 必须与修改前一致。

- 方法/顶层函数按名称、短说明、参数表、返回值组织；返回值为所属 API 的下一层标题及「名称 / 类型 / 默认值 / 说明 / 必传」表。类型从 AST 获取，说明从 dartdoc 的「返回值」章节获取，无说明时显示 `-`，不从类型或参数猜测；保留 dynamic/泛型返回类型；void 无返回值，不生成空的返回分组，校验仍依据源码 void 类型。消费审计兼容旧行内返回类型及新返回表，独立比对返回类型并隔离参数/行为/返回表，避免混读或借用相邻 API。Popup.show 的两行行为表合并为一句，其返回说明由源码维护。官网 API 六级标题维持语义层级，字号不小于正文，其后的表格随内容区宽度并支持说明换行，保证可读性。按 presentation-rules.md 推广至全部组件。

### 类型别名表格展示追加要求

回调 typedef 不重复显示 Dart 声明：四级「回调参数」和「返回值」均使用统一五列表头。参数类型、顺序、必传状态及返回类型由 AST 提取，说明使用标准 dartdoc 参数段落和返回值章节，不由名称猜测。回调的 void 返回也明确显示为 void；无参数的回调显示无参数，不生成空表。类型别名泛型、回调自身泛型、可空性和位置参数顺序必须保留。非函数别名以「类型定义」表展示目标类型。独立消费审计须比对这些契约，并兼容旧资产的完整 typedef 声明。逐组件重新生成和验收全部 API，运行 Token 保持一致。

### API 数据表统一列追加要求

参数、返回值、属性、静态成员及枚举值的数据表统一为「名称 / 类型 / 默认值 / 说明 / 必传」。非输入数据的必传为 `-`；返回值与枚举不虚构默认值，名称分别为「返回值」和实际枚举值，类型来自 AST。参数表保持源码 required 和默认值语义。返回表仍属于所属方法，其五列表头不得被审计器误读为参数，兼容旧两列返回表和行内返回类型。所有组件使用同一规则生成。说明性关系表也统一五列：首列作为名称，其余原有列的标题和值合并至说明，不适用项为 `-`；保留全部关系与转义竖线。通过不可见的表格角色标记将说明表与参数契约隔离，审计器不得借用说明表补足缺失参数。
