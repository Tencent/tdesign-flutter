## 背景与目标

以下保留设计形成时的问题与依据；已修复的问题不表示当前代码仍有同一缺陷。

阶段准备、旧 CI 或 PR 合并不能证明最终候选及线上产物来自同一版本，尚有跨组件门槛需要承接。

发布流程由 [PUBLISH.md](../../../PUBLISH.md) 维护；本 Spec 只承接尚未关闭的跨组件发布门槛，避免将旧版号升级、准备阶段完成或 PR 合并当成正式放行。

## 范围与非目标

覆盖本工程职责的设计与验收边界；不将目录整理扩展为新的组件能力、发布动作或远端配置修改。

## 最终方案与行为契约

### 候选契约

- 冻结目标版本、完整源码 SHA、SDK、依赖与构建来源；功能、迁移、Golden、设备、设计和交付产物各自提供对应候选证据。
- 组件、示例版本和构建元数据一致；构建日期来自实际打包，不在启动时伪装为当天发布。
- 包、tag、站点、APK 等交付物核对同一来源；合并 release PR、tag 创建或旧 CI 通过均不等于正式交付成功。
- 缺少设备、设计裁定、迁移或线上消费证据时保持未完成。文档整理、目录迁移不核销真实发布门槛。

### 维护边界

[待验收事项](./readiness.md) 和 [人工验收表](./manual-acceptance.md) 中的日期、SHA 和结果是原记录快照，不能视为当前远端或发布状态。本轮不查询或改变远端状态、不发布；下一次实际发布必须重新绑定候选和检查当前工作流。

历史的 1.0 版本升级方案、PR 依赖顺序及阶段准备记录已移除。一般发布操作继续维护 PUBLISH.md；本轮验收关闭后，可将通用门槛归入 PUBLISH.md，再移除这份临时发布 Spec。

## 关键决策与取舍

| 决策 | 理由与取舍 |
| --- | --- |
| 采用的方案 | 发布步骤归 PUBLISH.md，本 Spec 暂存候选绑定、人工验收和来源一致性门槛。 |
| 保留的边界与代价 | 不把旧版本号方案、PR 顺序和历史绿灯作为当前状态；门槛关闭后可归入发布流程并移除临时 Spec。 |

## 兼容性与迁移

本次只整理设计记录，不据此新增 API、改变默认值或判断全部兼容。后续接口删除、类型收紧或默认行为变化按最终源码和迁移指南核对。

## 验收标准

- 默认、显式配置、关键状态与边界行为符合最终方案；功能、视觉和人工路径按适用范围分别验收。

验收标准描述应满足的行为，不表示已执行或通过；执行范围与证据见 [acceptance.md](./acceptance.md)，剩余事项只在 [tasks.md](./tasks.md) 维护。

## 未使用版本工具清理

VersionUtil 与 kIsFlutterWebAfter320 位于内部 src/util，未由包入口导出，库内无调用。删除该历史实现与重复/空注释，不新增版本探测、不改 SDK 约束、组件 API 或默认行为。依赖 package:tdesign_flutter/src/util/version_util.dart 的外部深层导入将失效，该内部文件不作为受支持入口保留；正式包入口用户无需迁移。冻结证据内的旧文件路径保留原样用于追溯。验收为全库引用/导出检查与 Flutter 双版本严格分析；清理不关闭设备、设计、Token 或发布门槛。
